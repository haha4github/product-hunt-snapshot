## Commands

```bash
npm ci                      # install dependencies (only ejs; Node >= 18 required — fetch uses the global fetch API)
PH_TOKEN=xxx npm run fetch  # fetch Product Hunt data → output/ (requires a Product Hunt API token)
npm run build               # render the static site → docs/
```

There are no tests or linters. Locally, `PH_TOKEN` comes from the environment (the README mentions a `.env` file, but nothing loads it — export the variable in the shell). In CI it comes from the `PRODUCT_HUNT_TOKEN` repository secret.

## Architecture

Two-stage pipeline that snapshots Product Hunt's front page and publishes a static visualization site via GitHub Pages:

1. **`scripts/fetch_producthunt.js`** — queries the Product Hunt GraphQL API (top 20 posts) and writes to `output/` (gitignored):
   - `posts-<timestamp>.json` — one immutable snapshot per run
   - `latest.json` — most recent snapshot
   - `summary.json` — accumulating time series (one point per fetch: vote totals, top 5 posts), capped at ~2200 points (~90 days hourly). It appends to whatever `output/summary.json` already exists — in CI that history is restored from the `data-archive` branch before fetching (see workflow). Losing that restore step resets the trends history to a single point.

2. **`scripts/build_site.js`** — renders `templates/*.ejs` into `docs/` and serializes the data from `output/latest.json` + `output/summary.json` into `docs/js/data.js` as a global `const phData = {latest, summary}`. All charting happens client-side: `docs/js/main.js` and `docs/js/trends.js` read `phData` and render with Chart.js (loaded from CDN, along with Bootstrap 5).

Generated by the build (do not hand-edit): `docs/index.html`, `docs/trends.html`, `docs/about.html` (inline HTML string in build_site.js, not a template), `docs/js/data.js`, `docs/sitemap.xml`, `docs/robots.txt`. Hand-maintained static assets in `docs/`: `css/styles.css`, `js/main.js`, `js/trends.js`.

**CI (`.github/workflows/frequent_snapshot.yml`)** runs hourly: restore `summary.json` from the `data-archive` branch → fetch → build → deploy `docs/` to `gh-pages` (served at https://haha4github.github.io/product-hunt-snapshot/) → archive `output/` back to `data-archive` (both with `peaceiris/actions-gh-pages`). The `data-archive` branch tip holds only the current run's files; older snapshots live in its commit history (and in `gh-pages` history before 2026-09).

## Gotchas

- Comments and console messages are a mix of Chinese and English; site-facing text is English.
- The site domain is hardcoded in `scripts/build_site.js` (sitemap + robots.txt) — update it if the repo moves.
